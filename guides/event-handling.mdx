The `tray-icon` crate emits mouse interaction events through `TrayIconEvent`. These events cover clicks, double-clicks, and cursor movement in and out of the tray icon region. You can receive them via a built-in channel or install a custom handler closure — the latter being the recommended approach when integrating with `winit` or `tao`, because it wakes the event loop immediately on each event. Menu item clicks are handled separately through `MenuEvent`, covered in the [Menus guide](/guides/menus).

## TrayIconEvent enum

`TrayIconEvent` is a non-exhaustive enum with five variants. Every variant carries the `id` of the tray icon that generated the event, plus the cursor `position` and the icon's bounding `rect`.

<Note>
`TrayIconEvent` is **not emitted on Linux**. The tray icon will still display and its context menu will still work, but no mouse events are fired. This is a limitation of `libappindicator`.
</Note>

### Click

Fired when any mouse button is pressed or released over the tray icon.

```rust
TrayIconEvent::Click {
    id: TrayIconId,
    position: dpi::PhysicalPosition<f64>,
    rect: Rect,
    button: MouseButton,
    button_state: MouseButtonState,
}
```

| Field | Type | Description |
|---|---|---|
| `id` | `TrayIconId` | The tray icon that was clicked |
| `position` | `PhysicalPosition<f64>` | Cursor position in physical pixels |
| `rect` | `Rect` | Bounding box of the tray icon |
| `button` | `MouseButton` | Which button triggered the event |
| `button_state` | `MouseButtonState` | Whether the button went `Down` or `Up` |

### DoubleClick

Fired on a double-click. **Windows only.**

```rust
TrayIconEvent::DoubleClick {
    id: TrayIconId,
    position: dpi::PhysicalPosition<f64>,
    rect: Rect,
    button: MouseButton,
}
```

### Enter, Move, Leave

These three variants share the same field layout and track cursor movement relative to the tray icon region.

```rust
// Cursor entered the tray icon region
TrayIconEvent::Enter { id, position, rect }

// Cursor moved within the tray icon region
TrayIconEvent::Move  { id, position, rect }

// Cursor left the tray icon region
TrayIconEvent::Leave { id, position, rect }
```

## MouseButton enum

```rust
pub enum MouseButton {
    Left,    // default
    Right,
    Middle,
}
```

## MouseButtonState enum

```rust
pub enum MouseButtonState {
    Up,    // default
```

## Receiving events

There are two mutually exclusive ways to receive `TrayIconEvent`. Choosing one disables the other.

### Option 1 — Channel receiver

`TrayIconEvent::receiver()` returns a reference to a `crossbeam_channel` `Receiver<TrayIconEvent>`. Call `try_recv()` anywhere in your loop to drain queued events non-blocking:

```rust
use tray_icon::TrayIconEvent;

let tray_channel = TrayIconEvent::receiver();

// Somewhere in your event/game loop:
while let Ok(event) = tray_channel.try_recv() {
    match event {
        TrayIconEvent::Click { button, button_state, .. } => {
            println!("Click: {button:?} {button_state:?}");
        }
        TrayIconEvent::Enter { .. } => println!("Mouse entered"),
        TrayIconEvent::Leave { .. } => println!("Mouse left"),
        _ => {}
    }
}
```

The channel approach works well for polling loops, but the event loop will **not** automatically wake when a tray event arrives — your loop must poll regularly.

### Option 2 — Custom event handler

`TrayIconEvent::set_event_handler` installs a `Send + Sync` closure that is called immediately each time an event is dispatched. When a handler is set, events are **no longer sent to the channel**.

```rust
use tray_icon::TrayIconEvent;

TrayIconEvent::set_event_handler(Some(|event: TrayIconEvent| {
    println!("Tray event: {event:?}");
}));

// Remove the handler and re-enable the channel receiver
TrayIconEvent::set_event_handler::<fn(TrayIconEvent)>(None);
```

<Tip>
The custom handler approach is ideal for `winit` and `tao` applications because you can forward events through an `EventLoopProxy`, which wakes the event loop on each tray event — avoiding the need to spin-poll.
</Tip>

## winit / tao integration

Both `winit` and `tao` provide `EventLoopProxy::send_event` to post custom events into the event loop from any thread. Combine this with `set_event_handler` to bridge tray events into the native event loop.

<Tabs>
  <Tab title="winit">
    ```rust
    use winit::event_loop::{EventLoop, EventLoopBuilder};
    use tray_icon::{TrayIconEvent, menu::MenuEvent};

    #[derive(Debug)]
    enum UserEvent {
        TrayIconEvent(tray_icon::TrayIconEvent),
        MenuEvent(tray_icon::menu::MenuEvent),
    }

    let event_loop = EventLoop::<UserEvent>::with_user_event()
        .build()
        .unwrap();

    // Forward tray icon events into the winit event loop
    let proxy = event_loop.create_proxy();
    TrayIconEvent::set_event_handler(Some(move |event| {
        proxy.send_event(UserEvent::TrayIconEvent(event));
    }));

    // Forward menu events into the winit event loop
    let proxy = event_loop.create_proxy();
    MenuEvent::set_event_handler(Some(move |event| {
        proxy.send_event(UserEvent::MenuEvent(event));
    }));
    ```

    Then handle them inside `ApplicationHandler::user_event`:

    ```rust
    fn user_event(
        &mut self,
        _event_loop: &winit::event_loop::ActiveEventLoop,
        event: UserEvent,
    ) {
        println!("{event:?}");
    }
    ```
  </Tab>
  <Tab title="tao">
    ```rust
    use tao::event_loop::EventLoopBuilder;
    use tray_icon::{TrayIconEvent, menu::MenuEvent};

    enum UserEvent {
        TrayIconEvent(tray_icon::TrayIconEvent),
        MenuEvent(tray_icon::menu::MenuEvent),
    }

    let event_loop = EventLoopBuilder::<UserEvent>::with_user_event().build();

    // Forward tray icon events
    let proxy = event_loop.create_proxy();
    TrayIconEvent::set_event_handler(Some(move |event| {
        proxy.send_event(UserEvent::TrayIconEvent(event));
    }));

    // Forward menu events
    let proxy = event_loop.create_proxy();
    MenuEvent::set_event_handler(Some(move |event| {
        proxy.send_event(UserEvent::MenuEvent(event));
    }));

    event_loop.run(move |event, _, control_flow| {
        match event {
            tao::event::Event::UserEvent(UserEvent::TrayIconEvent(e)) => {
                println!("Tray: {e:?}");
            }
            tao::event::Event::UserEvent(UserEvent::MenuEvent(e)) => {
                println!("Menu: {e:?}");
            }
            _ => {}
        }
    });
    ```
  </Tab>
</Tabs>

## MenuEvent integration

`MenuEvent` (from `tray_icon::menu`) follows exactly the same two-pattern API as `TrayIconEvent`.

```rust
use tray_icon::menu::MenuEvent;

// Pattern 1 — channel
let menu_channel = MenuEvent::receiver();
if let Ok(event) = menu_channel.try_recv() {
    println!("Menu item clicked: {:?}", event.id);
}

// Pattern 2 — custom handler
MenuEvent::set_event_handler(Some(|event: MenuEvent| {
    println!("Menu item clicked: {:?}", event.id);
}));
```

See the [Menus guide](/guides/menus) for details on matching `event.id` to a specific `MenuItem`.

## Identifying the source tray icon

Every `TrayIconEvent` variant carries a `TrayIconId`. If your application has multiple tray icons you can use this id to route events:

```rust
use tray_icon::{TrayIconEvent, TrayIconId};

let tray_channel = TrayIconEvent::receiver();

if let Ok(event) = tray_channel.try_recv() {
    match event.id() {
        id if id == "main-tray" => { /* handle main tray */ }
        id if id == "secondary-tray" => { /* handle secondary tray */ }
        _ => {}
    }
}
```

`TrayIconEvent::id()` is a convenience method that extracts the `&TrayIconId` from any variant without needing to pattern-match on each one.
