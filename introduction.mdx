`tray-icon` is a Rust library that lets you create and manage system tray icons for desktop applications. It provides a clean builder API for attaching icons, tooltips, and context menus to the system tray, along with a channel-based event model for reacting to mouse clicks and hover interactions — all from a single, cross-platform codebase.

## What Is tray-icon?

`tray-icon` is the crate that powers Tauri's built-in tray icon support. It abstracts over the native system tray APIs on each platform — the Win32 notification area on Windows, `NSStatusItem` on macOS, and `libappindicator`/`libayatana-appindicator` on Linux — so you get a consistent interface without writing platform-specific code yourself.

The crate pairs with [`muda`](https://github.com/tauri-apps/muda) for context menus, which is re-exported as `tray_icon::menu` so you never need to add `muda` as a separate dependency.

## Supported Platforms

`tray-icon` runs on all major desktop operating systems:

| Platform | Status | Event Loop Requirement |
|---|---|---|
| **Windows** | ✅ Supported | Win32 event loop on the same thread as the tray icon |
| **macOS** | ✅ Supported | Event loop must run on the main thread; create the icon after the loop starts |
| **Linux** | ✅ Supported (GTK only) | GTK event loop on the same thread as the tray icon |
| **FreeBSD** | ✅ Supported (GTK only) | GTK event loop on the same thread as the tray icon |

### Platform-Specific Notes

- **Windows & Linux/FreeBSD:** The event loop does not need to run on the main thread, but the tray icon must be created on the same thread that runs the loop.
- **macOS:** The event loop _must_ run on the main thread, so the tray icon must also be created on the main thread. Additionally, the event loop must already be running before you create a `TrayIcon` — with Winit, the earliest safe point is the [`StartCause::Init`](https://docs.rs/winit/latest/winit/event/enum.StartCause.html#variant.Init) event.

## The `tray_icon::menu` Module

`tray-icon` re-exports the entire [`muda`](https://github.com/tauri-apps/muda) crate under `tray_icon::menu`. This means you get access to `Menu`, `MenuItem`, `PredefinedMenuItem`, `MenuEvent`, `AboutMetadata`, and more without listing `muda` in your own `Cargo.toml`.

```rust
use tray_icon::menu::{Menu, MenuItem, PredefinedMenuItem, MenuEvent};

let tray_menu = Menu::new();
let quit_item = MenuItem::new("Quit", true, None);
tray_menu.append(&quit_item).unwrap();
```
